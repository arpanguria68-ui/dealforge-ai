Reports & review gate

Reports are edited, not concatenated agent output. A deterministic pipeline turns persisted agent results into an evidence brief, an editorial layer trims and deduplicates, and renderers produce four formats.

1
Collect

Completed task results become agent_results; activity metadata is attached.

2
Evidence brief

Data points with period, source and basis; source register (SEC filing index links); findings, gaps and metric conflicts.

3
Editor

Key messages, per-agent summaries and a recommendation line. A deterministic fallback runs when no model is available. Unusable memos are flagged, not rendered.

4
Render

python-docx, python-pptx, openpyxl and ReportLab/fpdf2, with Plotly charts (Matplotlib fallback).

5
Validate

Structural checks on each artifact; text is cleaned (LaTeX markup, mojibake) before it reaches a document.

6
Review gate

Each artifact carries release_status; clients download approved reports only.

The four formats

FormatTypical contents
Word (.docx)Cover, contents, Evidence coverage & review status, metric reconciliation, executive summary with key messages, financial metrics with sources, per-agent findings, valuation and LBO tables, charts, full agent appendix, source register
PowerPoint (.pptx)15 slides: title, executive summary, recorded metrics, revenue bridge, football field, valuation table, key messages, findings by agent, risks, takeaways, recommendation (clearly labelled as a draft), source register
Excel (.xlsx)10 sheets: Executive Summary, Editor Brief, Income Statement, DCF Analysis, Comps, LBO Returns, Risk Matrix, Agent Analysis Detail, Sources & References, Evidence Brief
PDFConcise 7-page version with the same key messages, evidence and charts

Release states

StateMeaningDownload behavior
pending_reviewGenerated, not approvedPlain download returns 409. Draft download (?draft=true) returns the file named …_DRAFT_not_approved with X-Release-Status: draft-not-approved
approvedA reviewer approved the report setNormal download

Endpoints

POST /api/v1/deals/{id}/documents/plan       # preview the document plan (optional {"request": "...", "fill_gaps": true})
POST /api/v1/deals/{id}/documents/generate   # build docx, pptx, xlsx, pdf
POST /api/v1/deals/{id}/documents/approve    # reviewer approval (admin token if enforced)
GET  /api/v1/deals/{id}/documents            # artifact list with release status
GET  /api/v1/deals/{id}/documents/{fmt}      # fmt = docx | pptx | xlsx | pdf   (?draft=true)
GET  /api/v1/deals/{id}/documents/bundle     # all four
GET  /api/v1/deals/{id}/exports/docx         # on-the-fly Word report (what the chat Report button uses)
GET  /api/v1/deals/{id}/exports/json         # structured analysis export

The recommendation in a report is the memo agent draft, shown with a label that it is model-generated and needs reviewer sign-off. DealForge does not compute an approved "deal score" in the chat flow; reports say "deal not scored" rather than invent one.
