Getting started

DealForge AI is a FastAPI backend plus a React UI. It needs Redis for deals, conversations and generated artifacts, and at least one LLM provider.

Requirements

ComponentVersionNotes
Python3.11+Backend (the Dockerfile uses python:3.11-slim)
Node.js20+Frontend build and dev server
Redis7Required. Docker Compose starts one; locally run redis-server
LLM accessany oneA cloud key (Gemini, OpenAI, Mistral, …), a local model (Ollama / LM Studio) or any OpenAI-compatible endpoint
Optional data keysFinnhub, Alpha Vantage, financial_datasets, FMP. SEC EDGAR needs no key

Option A · Docker Compose

git clone https://github.com/arpanguria68-ui/dealforge-ai.git
cd dealforge-ai
# create .env.docker with your keys (see the table below), then:
docker compose --env-file .env.docker up --build -d

The UI is served on http://localhost:3000 and the API on http://localhost:8005 (interactive docs at /docs). Generated reports persist in the dealforge-reports volume.

Option B · Local development

# 1. Redis
redis-server

# 2. Backend (from the repository root)
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8005

# 3. Frontend (second terminal)
cd frontend
npm install
npm run dev

The frontend talks to <current-host>:8005 by default; override with VITE_API_BASE. The backend allows the origins localhost:3000, 3001, 5173, 5174 out of the box; set CORS_ORIGINS for anything else.

Configure a model

Open Settings in the UI and add a provider key, or set the environment variables below. To use any OpenAI-compatible server (a local gateway, vLLM, a proxy), choose Custom endpoint and give it a base URL, model name and key. Per-agent routing is stored in settings.json and can pin individual agents to individual providers.

Keys are masked in the UI and are never sent to the browser in full. Do not commit settings.json or .env files: the repository ignores them.

VariablePurpose

Your first analysis

1
Open the Chat tab and click New Analysis

The welcome message explains the flow.

2
Type a deal

For example: Evaluate a take-private of Sprout Social (NASDAQ: SPT). Proceed with public data only; do not ask clarifying questions. Saying you do not want questions skips the clarification step.

3
Review the plan

The Scrum Master lists the tasks and the agent for each. A valuation agent is added automatically whenever a DCF or LBO is planned.

4
Click Approve & run

Agents run in dependency order. Expect several minutes with a remote chat-style model; local models vary.

5
Read the brief, then open the Dashboard

Use View Analysis → Generate for the documents; a reviewer approves them for release.

Tests

cd backend
pytest -q

The suite has 448 tests. Two tests fail on Windows for environmental reasons (symlink privilege and hard-coded Windows paths); they are unrelated to behavior.

Troubleshooting

SymptomLikely cause
The UI loads but every call failsBackend not on port 8005, or the UI origin is missing from CORS_ORIGINS
Backend exits on startRedis is not running or REDIS_URL is wrong
Agents return "tool request" text or empty resultsThe model does not support native tool calls; use a provider that does, or the OpenAI-compatible endpoint (which uses the built-in text tool protocol)
Report downloads return 409Reports are not approved yet; use the draft download (?draft=true) or approve them from the Dashboard
No peer multiples in compsFinnhub key missing or rate limited; the valuation agent records this under "Not retrieved"
